# Watchers Infrastructure

The Watchers infrastructure is a critical component of the Lynxion ETS (Enterprise Trading System) that implements the first part of the complete workflow: **Watcher → Engine → Fusion → Strategy → Broker**. This system monitors market conditions continuously and identifies trading opportunities based on technical analysis, market sentiment, and statistical patterns.

## Overview

The Watchers infrastructure provides real-time market monitoring capabilities that detect potential trading opportunities. Each watcher specializes in a particular aspect of market analysis and generates signals when specific conditions are met. The system is designed with hexagonal architecture principles to maintain clean separation of concerns and ensure testability.

## Architecture

### Core Components

The architecture follows a clean, modular design with the following key components:

```
┌─────────────────┐    ┌──────────────────┐    ┌─────────────────┐
│   Watcher Port  │◄──►│  Base Watcher    │◄──►│ Concrete Watcher │
│   (Domain)      │    │  (Infrastructure)│    │  (Infrastructure)│
└─────────────────┘    └──────────────────┘    └─────────────────┘
                              │
                              ▼
                    ┌──────────────────┐
                    │  Watcher Service │
                    │  (Application)   │
                    └──────────────────┘
```

### Key Interfaces

- **WatcherPort**: Domain interface defining the contract for all watchers
- **BaseWatcher**: Abstract base class implementing common watcher functionality
- **Concrete Watchers**: Specialized implementations for specific market analysis

## Watcher Types

The system includes several specialized watchers, each focusing on different aspects of market analysis:

### 1. MarketPulseWatcher
Analyzes market sentiment and momentum using price trends, volume changes, and momentum indicators.

**Features:**
- Momentum calculation based on recent price changes
- Trend strength analysis using linear regression
- Volume factor assessment
- Combined signal scoring

### 2. VolatilityWatcher
Monitors market volatility patterns and identifies potential breakout or mean reversion opportunities.

**Features:**
- Volatility measurement using standard deviation
- Bollinger Bands analysis
- ATR-based volatility assessment
- Volatility regime detection

### 3. TrendMTFWatcher (Multi-Timeframe Trend)
Analyzes trends across multiple timeframes to identify aligned market direction.

**Features:**
- Multi-timeframe trend alignment analysis
- Short, medium, and long-term trend tracking
- Trend strength assessment
- Cross-timeframe divergence detection

### 4. AnomalyMLWatcher
Uses machine learning algorithms to detect unusual market patterns and anomalies.

**Features:**
- Statistical anomaly detection
- ML-based pattern recognition
- Outlier identification
- Predictive anomaly scoring

### 5. OrderFlowWSWatcher
Monitors order book dynamics and market microstructure for institutional positioning clues.

**Features:**
- Real-time order book analysis
- Large order detection
- Order flow imbalance metrics
- Liquidity sweep identification

### 6. CMCScreener
Integrates with CoinMarketCap API to screen for coins with specific fundamental characteristics.

**Features:**
- Market cap-based screening
- Volume and liquidity analysis
- Trending coin detection
- Fundamental metrics evaluation

### 7. FundingRateWatcher
Monitors funding rates for perpetual futures to identify potential market sentiment shifts.

**Features:**
- Funding rate analysis
- Sentiment assessment
- Potential reversal indicators
- Funding arbitrage opportunities

### 8. LiquidityWatcher
Identifies liquidity levels and potential sweep zones for institutional-style trading.

**Features:**
- Liquidity level identification
- Potential sweep zone detection
- Market maker positioning analysis
- Order flow dynamics

### 9. HistoricalCandleWatcher
Analyzes historical candlestick patterns and price action for technical signals.

**Features:**
- Candlestick pattern recognition
- Historical price action analysis
- Support and resistance identification
- Reversal pattern detection

## Integration Points

### With Brokers
Watchers can be configured to work with specific brokers:
- **BingX**: Primary integration for spot and futures trading
- **Configurable target broker**: Each watcher can specify which broker to work with

### With Strategies
Watchers feed signals to the Strategy layer:
- Signals generated by watchers trigger strategy execution
- Confidence levels influence position sizing
- Metadata provides context for strategy decisions

### With Risk Management
- Stop Loss and Take Profit levels calculated based on watcher signals
- Position sizing influenced by signal confidence
- Risk controls applied to all watcher-generated signals

## Usage

### Basic Implementation
```python
from infrastructure.watchers.adapters.market_pulse import MarketPulseWatcher
from domain.value_objects import Symbol

# Create a watcher instance
watcher = MarketPulseWatcher(
    name="MyMarketPulse",
    symbol=Symbol("BTCUSDT"),
    broker_service=broker_service,
    target_broker="bingx"
)

# Update with market data
watcher.update_data({
    'close': 45000.0,
    'volume': 1000.0
})

# Generate signal
signal = watcher.analyze(Symbol("BTCUSDT"))
```

### Signal Processing
Watchers generate signals with the following properties:
- **Signal Type**: BUY, SELL, or HOLD
- **Confidence**: 0.0 to 1.0 indicating signal strength
- **Score**: -1.0 to 1.0 normalized signal strength
- **Metadata**: Additional information about the signal source and conditions
- **Timestamp**: When the signal was generated

## Risk Management Integration

The watchers integrate with the risk management system by:
- Providing confidence levels that affect position sizing
- Including metadata for risk assessment
- Supporting dynamic SL/TP calculation based on market conditions
- Ensuring proper risk controls before signal propagation

## Performance Considerations

- **Efficient data buffering**: Watchers maintain limited data buffers to prevent memory issues
- **Rate limiting**: Built-in delays to respect API rate limits
- **Selective signal emission**: Only emits signals that differ significantly from previous ones
- **Thread-safe operations**: Designed for concurrent execution

## Error Handling

- **Graceful degradation**: If one watcher fails, others continue operating
- **Logging integration**: Comprehensive logging through the EnhancedLogger
- **Retry mechanisms**: Automatic retries for transient failures
- **Fallback strategies**: Alternative data sources when primary sources fail
