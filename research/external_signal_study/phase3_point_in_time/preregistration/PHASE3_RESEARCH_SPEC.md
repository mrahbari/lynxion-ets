These differences are not trading returns, executable edge, or HMT rules.

## Six primary feature formulas (no further primary families)

For a timestamp T, resample source 15m candles into 1h/4h/1d using UTC boundaries and **only completed component candles**. Let `C_k`, `H_k`, `L_k`, `V_k` be closed 15m bars; `s=+1` LONG, `-1` SHORT. Denominators `max(x, 1e-12)` guard zero. Every rolling window excludes the incomplete bar at T. Continuous features are not thresholded for the primary test. Features are computed identically for cases and controls:

1. `F1 directional_4h_return`: `s * log(C_4h,last / C_4h,4bars_prior)`, four completed 4h bars.
2. `F2 range_location_20`: `s * (2*(C_last - min(L_last20))/(max(H_last20)-min(L_last20)) - 1)` on 20 completed 15m bars; missing if zero range. This is an objective structure/location proxy, not proof of HH/HL.
3. `F3 countertrend_pullback_8`: `-s * log(C_last / C_8bars_prior)` on eight completed 15m bars. It measures movement against announced side, not a reconstructed impulse rule.
4. `F4 compression_ratio`: `(max(H_last8)-min(L_last8)) / (max(H_last32)-min(L_last32))`, completed 15m bars; missing if 32-bar range zero.
5. `F5 relative_volume_8`: `sum(V_last8) / mean(sum(V_8bar block) over preceding 20 nonoverlapping blocks)`. Require all 168 completed 15m bars and positive denominator; no forward normalization.
6. `F9 BTC_directional_4h_return`: `s * log(BTC_C_4h,last / BTC_C_4h,4bars_prior)` from same source/close rules. This is market context, not an HMT mechanism claim.

No primary feature is computed from funding/OI, liquidation, semantic prose, chart geometry, image-derived stop/target, or future performance. F6 MTF alignment is represented only by the two prespecified 4h returns above; do not add hidden indicators. F7 liquidity levels, F8 risk geometry, and F10 macro calendar are deferred secondary families because currently reliable objective case/control parity is not established. Their absence cannot be used to claim a universal null fingerprint. Any additional feature family requires an append-only amendment **before** opening its data, and is never primary in this run.

## Statistical plan and power gate

For each feature, calculate per-case `case_value - mean(valid Family-A controls)`; controls never count as independent N. Report paired median/mean difference, pooled robust-standardized difference (using predeclared pooled median absolute deviation; missing if zero), and 95% confidence intervals from 10,000 **UTC-day-cluster** bootstrap resamples; preserve all same-day symbols as one cluster. Report nominal case count, matched count, independent UTC days, symbol breadth, side/timeframe breadth, and missingness. Primary two-sided tests: sign-flip permutation at UTC-day-cluster level, 10,000 deterministic draws with seed `31004`; six p-values adjusted by Benjamini–Hochberg FDR at q=0.10. If fewer than 10 independent days, no p-value-based claim. Simple logistic classification is secondary only, with chronological grouped folds and no random row split; skip if fewer than 40 matched cases across 20 days. No ML search.

Prespecified practically meaningful standardized magnitude is `|d| >= 0.40` for a single feature. Compute detectable effect and CI width using observed pre-T feature dispersion/matching covariance only, not returns or outcomes; include symbol/day clustering and missingness. Adequately powered requires >=80% estimated power to detect d=0.40, at least 40 matched cases, 20 distinct UTC days, 10 symbols, and both sides represented by >=10 cases each. Marginal if 60–79% power with breadth met; otherwise underpowered. Bootstrap/simulation must preserve case-control groups, UTC-day clusters, and symbol membership, with deterministic seed `31005`. No outcome data in power simulation. These thresholds are intentionally strict; the current 58 nominal/25-day HMT pool may be underpowered after matching.
