## Public source feasibility and causal contract

Binance's public USD-M WebSocket `depth` stream plus public `GET /fapi/v1/depth` snapshot is the narrow source pair for a reconstructable book. Binance's [local-book procedure](https://developers.binance.com/en/docs/products/derivatives-trading-usds-futures/websocket-market-streams/How-to-manage-a-local-order-book-correctly) requires buffering updates, snapshot `lastUpdateId`, discarding old events, initial `U <= lastUpdateId <= u`, then consecutive `pu == prior u`; otherwise reinitialize. Absolute price-level quantities are applied; zero deletes a level. Public [REST market-data catalog](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/market-data) identifies `/fapi/v1/depth`, `/fapi/v1/aggTrades`, and `/fapi/v1/ticker/bookTicker`. These are **market-data**, not account/trading endpoints. Source documentation does not make missing historical update sequences reconstructable. Current endpoint availability from this machine was **not tested**; geographic/network access and exact per-IP rate limits remain unknown and must be checked before activation without authentication. No alternative exchange/source is silently substituted.

The [public Binance archive README](https://github.com/binance/binance-public-data) supports raw futures aggTrades/trades with trade timestamp, ID, price, quantity and buyer-maker flag. It does not turn trade events into resting-book observations. Historical archived `bookDepth` supplies signed percentage bands but not `U/u/pu` or price-level best quotes. Public book-ticker availability should be verified separately; even a complete quote archive would give BBO, **not** full L2 reconstruction without depth updates/snapshots.

Minimum scientific information contract for **measurement only**: venue/market/symbol; raw depth snapshot (`lastUpdateId`, full returned levels, request/receipt times); each raw diff event (`E`, `T` where supplied, `U`, `u`, `pu`, price/absolute quantity level changes, local monotonic receipt time and UTC wall receipt time); connection/session ID and reconnect/gap markers; normalized *derived* best bid/ask, quantities, spread, book state version and valid-since time only when the sequence is continuous. Preserve raw text/bytes before parsing and record schema/version/units. AggTrades (aggregate ID, price, qty, `T`, buyer-maker flag and receipt clock) are **optional to this book-measurement gate**, not an assumed component of a future feature. No OBI/CVD threshold or signal formula is selected.

For a hypothetical decision at `T_decision`, admit only a validated book state fully reconstructed from events actually **received** by `T_decision`; require source event/transaction times `<= T_decision` as consistency checks, but do not use an exchange event merely because its timestamp predates a decision if the collector received it later. Cross-stream ties are resolved by observed receipt order plus a deterministic capture sequence, never favorable price movement. Mark unsynchronized clock epochs, stale snapshots, gaps and reconnect intervals **unavailable**; no future fill or retrospective interpolation. Source `E` (message event), `T` (transaction/book update where present), `U/u/pu` (sequence), local receipt and decision time are separate fields. Do not use SetupEngine's wall clock for this measurement boundary.

## Proposed collection specification — **NOT ACTIVATED**

This is a **proposed** contract to freeze in a separate approval/activation artifact, not a running feed and not a V3 preregistration.

1. **Source/cohort:** public, unauthenticated Binance USD-M Futures `btcusdt@depth@100ms` and `ethusdt@depth@100ms`, with public `/fapi/v1/depth?symbol=<symbol>&limit=1000` snapshots after each connection/recovery. Verify current stream URL/limits from exchange documentation at activation. No account, API key, signed endpoint, VST or order API.
2. **Immutable raw:** append-only per-symbol/per-UTC-day compressed message envelopes containing exact WebSocket payload bytes, collector monotonic receive counter, UTC receipt time, monotonic clock value, session ID and transport status; append raw REST snapshot response bytes plus request/response UTC/monotonic times. Do not overwrite or backfill a live gap. Separate derived validation output from raw capture.
3. **Manifest:** source/documentation version, endpoint, symbol, subscription and collector version, UTC start/stop, host clock-sync/offset evidence, reconnect epochs, raw filenames/bytes/row counts/SHA-256, snapshot IDs, per-epoch first/last `U/u/pu`, completeness and excluded intervals; write a signed-off boundary *before first observation*. Atomic daily finalization and checksum verification on reopen. A restart creates a new epoch/snapshot, never a seamless inferred continuation.
4. **Integrity gate:** apply the exchange's snapshot+diff bridging rule and `pu` chain. Any mismatch, malformed timestamp/quantity, crossed/empty derived book, impossible receipt ordering, local clock jump or dropped capture record invalidates that interval until a fresh snapshot establishes continuity. Record disconnects, throttling and data-loss reasons. No synthetic repair, no historical REST snapshot backfill.
5. **Duration/readiness:** first a bounded seven-complete-UTC-day *integrity pilot* only, to measure uptime, gap rate, message volume and storage; seven days is an engineering sizing period, **not** an Edge sample floor. A later prospective research duration/power floor must be set in a separately frozen outcome-blind protocol, using independent UTC-day clusters rather than treating each update as independent. If the pilot has an unqualified epoch, report it rather than extending the sample opportunistically.
6. **Storage budget:** plan from measured pilot bytes, not an asserted exchange rate. At 1,000 bytes/message and ten events/s/symbol as a capacity scenario, two symbols would be ~1.73 GB/day uncompressed (~12.1 GB/7 days), plus snapshots and hashes. Actual traffic and compression remain **UNKNOWN**; require disk-reserve/quota check before activation. Event frequency is not effective statistical N.
7. **No-backfill:** prospectively collect only observations after a pre-recorded activation boundary. Existing official archived trades/band depth may serve context only under a separately frozen alignment rule; they cannot fill a missing local quote/depth interval.

## Decision and remaining unknowns

**`PROSPECTIVE_MICROSTRUCTURE_COLLECTION_REQUIRED`.** Existing observed data are substantial but partially overlap already rejected C-18/C-19/flow hypotheses. A novel, continuously sequenced price-level BBO/L2 cohort is not locally qualified. Historical public `bookTicker` listing/schema/coverage could merit a separate provenance check, but cannot be assumed equivalent to complete book reconstruction; historical L2 update/snapshot history with `pu` continuity remains unproven. This result says **nothing** about predictive information or profitability.

**Exact next operator decision:** approve or decline freezing/activating the bounded seven-day, public-data-only integrity pilot above (including storage/network exposure) after endpoint/access and local disk checks. If a historical quote archive is preferred instead, authorize that *separate* outcome-free provenance qualification first; do not silently treat it as the same book contract. No long-running collection begins under this report alone.
