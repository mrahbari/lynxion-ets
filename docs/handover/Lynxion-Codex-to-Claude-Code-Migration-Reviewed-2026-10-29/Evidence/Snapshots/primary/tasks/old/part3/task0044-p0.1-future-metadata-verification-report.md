# 4. FAILURE PATHS

| Failure Path Scenario | Classification | Cause & Impact | Severity |
| :--- | :---: | :--- | :---: |
| **Missing Arguments in `record_intent()`** | **FACT** | `MultiBrokerService` calls `record_intent(sym, side, qty, broker, coid)`, omitting `stop_loss`, `take_profit`, `confidence`, `regime`. Metadata fields are not written to `live_order_journal.json`. | High |
| **BingX TPs/SLs Placed as Separate Orders** | **FACT** | BingX handles Take Profit and Stop Loss as separate trigger orders (`TAKE_PROFIT_MARKET`, `STOP_MARKET`) with distinct `orderId`s, but sharing the **same `positionID`**. Joining by `positionID` recovers entry/exit fills cleanly, but exit orders do not carry original entry metadata. | Medium |
| **Broker Reconciliation Generated Orders** | **INFERENCE** | Emergency unwind or reconciliation orders generated by `BrokerReconciliationService` do not originate from `DecisionPipeline` and will lack strategy metadata (recorded as `strategy="trend_following"`, `confidence=""`). | Low |
| **System Restart / Memory Reset** | **FACT** | `TradeFeatureCollector` reads directly from disk (`data/live_order_journal.json`), making metadata resolution fully persistent across application restarts. | Resolved |
