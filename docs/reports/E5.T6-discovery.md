**Discovery only — no code changes, no moves, no commits, no implementation plan beyond
boundary identification.** Acceptance (task): each CLI imports only `bootstrap` + use-cases
and contains no domain/infra logic.

## Headline
The CLIs were already largely thinned in E2. **None imports `infrastructure` or (except one
enum) `domain`** — all import `bootstrap` + `application.use_cases`. So T6 is mostly
**verification + a few targeted extractions**, not a 14-file rewrite. The real work:
(a) embedded business logic in `resync.py`; (b) the `sync_approved_symbols.py` legacy-runner
delegation; (c) optional consolidation of multi-`resolve()` "fat wiring" into the composition
root.

## 2. Importer / caller graph
- CLIs are **leaf entrypoints** — nothing imports them (they are run as `__main__` / via runner shims).
- Direction: `interface/cli/* → bootstrap.{container,lifecycle,settings} + application.use_cases.* (+ one domain enum)`. No CLI imports `infrastructure` or another CLI.
- **`trading_system_production.py → run_auto_detection / production_trading_orchestrator`** — couples it to **E5.T4** (thin it *after* T4 = "T6b").
- **`sync_approved_symbols.py → runner_sync_approved_symbols.py`** (root-level legacy runner, present, 5288 B) — the only CLI not on the bootstrap/use-case pattern.

## 3. Embedded business logic (the bits that violate "no logic in CLI")
- **`resync.py:74–93`** — symbol-selection + normalization in `main()`: filters enabled env symbols, then a nested loop normalizing each symbol against quote bases (`['USDT','USD','BTC','ETH']`) into `normalized_symbols`. **This is application logic, not parse/render** → extract to the sync use-case (or an application helper). *(Note: this is CLI-level arg normalization, distinct from — and must not touch — the frozen E4 `to_symbol`/DTO layer.)*
- **`sync_approved_symbols.py`** — orchestrates fetch → count → path-resolution → file-write by calling the legacy root runner; the actual logic lives in `runner_sync_approved_symbols.py`. Path resolution is **deliberately byte-identical** to the legacy entry point.
- **`backtest.py`** — `_parse_date` + a large `build_parser`; these are *parsing*, acceptable in a CLI. The `StrategyType` enum import is for arg validation (benign, but technically beyond "bootstrap + use-cases only").
- All other "logic signals" are **result rendering** (loops/appends building printed summaries) — allowed under `render`.

## 4. Separation: wiring / orchestration / business logic
- **Pure wiring (parse + 1 resolve + use-case call + render):** `walkforward`, `multitimeframe_update`, `historical_data_sync`.
- **Fat wiring (multi-`resolve()` injected into a use-case constructor):** `comprehensive_validation` (7), `extended_horizon_validation` (7), `retune` (5), `trading_system_modes` (4), `backtest` (4), `resync` (4), `shadow_deployment`/`history_download`/`comprehensive_portfolio_backtest` (3). The CLI assembles dependencies the **composition root** should own. Relocating this into a bootstrap factory (CLI resolves one ready use-case) is behavior-neutral.
- **Business logic in CLI:** `resync` (symbol normalization); `sync_approved_symbols` (fetch/update orchestration via legacy runner).
- **Render:** present in nearly all (allowed).

## 6. Proposed extraction boundaries (identification only — NOT an implementation plan)
- **Fat wiring → composition root:** for each MEDIUM CLI, the dependency-assembly (the N `resolve()` calls + use-case construction) is the extraction unit → a bootstrap/container factory that returns a ready use-case; the CLI keeps only parse + `resolve("<use_case>")` + call + render.
- **`resync` business logic:** the symbol-selection/normalization block (`:74–93`) is the extraction unit → into `SyncMarketDataUseCase` (or an application input-normalizer). CLI keeps raw arg parsing only.
- **`sync_approved_symbols`:** boundary = wrap `runner_sync_approved_symbols.fetch/update` behind an application use-case (+ a port for the HTTP fetch/file write), preserving the exact JSON path. Until then it is a documented exception.
- **`backtest` enum:** boundary = move strategy-type parsing/validation into the use-case request, or accept the enum import as a sanctioned parsing dependency (decision needed).
- **Render** stays in the CLI in all cases.

## 7. Proposed execution order for T6 (safe → risky)
1. **Verify SAFE set** (no-op/trivial): confirm the 6 SAFE CLIs already satisfy the acceptance; document any one-line cleanups.
2. **MEDIUM fat-wiring consolidation**, one CLI per step: `comprehensive_validation` → `extended_horizon_validation` → `retune` → `backtest` → `trading_system_modes` (keep its legacy `--mode backtest` path intact).
3. **`resync`** — extract the embedded normalization logic (MED-HIGH).
4. **`trading_system_production`** — only **after E5.T4** (it consumes the orchestrator) = "T6b".
5. **`sync_approved_symbols`** — last (HIGH): use-case wrapper + byte-identical path preservation; coordinate with the legacy root runner.

## Constraints / notes

- T6 must not touch the frozen E4 layers (`domain/`, `application/dto/`, ingestion) or broker/execution logic. The `resync` normalization extraction targets the *sync* use-case, not the E4 `to_symbol`/DTO mapper.
- Behavior-parity validation (CLI runs) is **not runnable in this environment** (no numpy/pandas/pytest); each T6 step needs a render/exit-code parity check in a test-capable venv.
