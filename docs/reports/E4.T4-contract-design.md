# E4.T4 — Contract Design Report (architecture stabilization, NO code)

Resolves the design decisions surfaced by the broker-boundary discovery
(`E4.T4-broker-boundary-discovery.md`) before any further wiring. **No code changes,
no wiring, no refactor, no commit.** These are binding decisions for the eventual
implementation phases.

Key grounding fact: the **domain `Order` already carries** `stop_price: Optional[Money]`,
`time_in_force: str = "GTC"`, `stop_loss_price: Optional[Money]`,
`take_profit_price: Optional[Money]` (added in E4.T1). So the gap is in the **transport
DTO + mapper**, not the domain model — no domain change is required.

---

## Decision 1 — ORDER CONTRACT EXTENSION → **YES (DTO + mapper only; domain unchanged)**

Extend `OrderDTO` and `order_to_domain()` to carry the risk parameters that the live
adapters already produce and that the domain already models. Do **not** touch the domain
`Order`.

Minimal safe schema extension (transport DTO — primitives only):
```
OrderDTO additional fields (all optional, defaults preserve current behavior):
  stop_price:     Optional[Number] = None
  stop_loss:      Optional[Number] = None      # -> Order.stop_loss_price
  take_profit:    Optional[Number] = None      # -> Order.take_profit_price
  time_in_force:  str = "GTC"
  position_side:  Optional[str] = None
```
`order_to_domain()` maps: the price-like fields → `Money` via `to_money(value, currency)`
(currency per Decision 3/Q-currency); `time_in_force` passthrough; `position_side` →
`PositionSide` when present.

**Rationale:** without this, migrating Order reads through the current `OrderDTO` silently
**drops `stop_price`/`time_in_force`** — a trading-critical regression. Because the domain
already supports the fields, this is a low-risk transport/mapper extension, not a domain
change. Optional fields with current-default values keep already-wired call sites (none yet)
unaffected.

## Decision 2 — SYMBOL NORMALIZATION POLICY → **A (strict canonical via `to_symbol()`)**

Make `to_symbol()` the single canonical normalizer: **strip whitespace, uppercase, and strip
separators (`-`, `/`, `_`)** → the system's established no-dash canonical form (`BTCUSDT`).

**Rationale:** this *subsumes* the bingx `replace("-","")` special case rather than
preserving it — `to_symbol("BTC-USDT")` → `BTCUSDT` reproduces bingx's current result, so
**there is no bingx regression and no per-adapter exception** (Option B's exchange-aware
branching is avoided). Outbound exchange formatting stays where it belongs
(`SymbolFormatHelper`, unaffected). Parity note: this slightly changes how `to_symbol`
handles already-dashed inputs, but the Phase-2A ingestion output dicts **contain no symbol
field**, so that wiring's *output* is unchanged; the effect is internal-only there. Net:
one canonical Symbol form everywhere, single choke point preserved.

## Decision 3 — MONEY MODEL STRATEGY → **B (hybrid): primitives at the seam, `Decimal`/`Money` in the domain**

- **Transport DTOs + adapter internals:** may use `float`/primitives (matches exchange
  payloads and existing scaling math like phemex `/1e8`).
- **Domain:** every domain entity is constructed **only via the mappers**, which coerce to
  canonical `Decimal`/`Money`. Domain entities therefore never *hold* float once migrated.
- **Do NOT add `__post_init__` coercion to domain entities now** — that is a broader,
  riskier domain change touching every constructor; defer it (candidate for a later
  hardening / mypy-strict rule under E6.T4). The mapper is the single coercion seam.

**Rationale:** full Decimal *through the adapters* (Option A literal) would force rewriting
float scaling/arithmetic across four adapters — invasive and regression-prone, violating
minimal-change/regression-safety. The hybrid keeps the messy float reality at the edge while
guaranteeing the domain is always canonical, which is the actual E4.T4 goal.

## Decision 4 — POSITION & BALANCE TYPE STRATEGY → **coercion mandatory AT the mapper; legacy float TEMPORARILY allowed until each site is migrated**

- The boundary coercion (`balance_to_domain`/`position_to_domain`) is **mandatory once a
  site is migrated** — no float/`Money`-in-wrong-field left in migrated domain objects.
- Until a given site is migrated, its current (raw) behavior **remains** — migration is
  **site-by-site, not big-bang** (regression safety).
- **Field-type rulings (resolves the discovery UNKNOWNs):**
  - `Balance.total/available/reserved` = **`Decimal`** (the entity contract). bingx's current
    use of `Money` in those fields is a **defect to correct** on migration (`Balance` already
    has `asset` + a `to_money()` helper; currency belongs there, not in the amount fields).
  - `Position.entry_price` / `unrealized_pnl` = **`Money`**. phemex's current `float`/str-side
    construction is a **latent bug**; migration corrects it (an intentional, reviewed change).
  - **Currency source (resolves the currency UNKNOWN):** derive from the symbol's quote asset
    via `Symbol.quote_asset()` (e.g. `BTCUSDT` → `USDT`) for price/PnL `Money`; for `Balance`,
    currency = the `asset` itself. No hard-coded `"USD"`/`"USDT"`. (Flag: `quote_asset()` is a
    heuristic for exotic pairs — acceptable canonical default, validate per exchange.)

**Rationale:** gives a single, consistent currency derivation and a clear target type per
field, while allowing a safe incremental rollout.

## Updated migration safety classification

**SAFE to migrate (low risk, well-defined)**
- `broker_manager.py` — no-op (pure delegator; confirm only).
- Symbol-construction sites once Decision 2 lands: `multi_broker_service` validation sites
  (`DomainSymbol(symbol)` → `to_symbol()`), and the `Symbol(item['symbol'])` calls inside
  Order reads (the symbol portion).

**UNSAFE (defined, but needs consumer audit + the contract changes first)**
- `Balance` sites (all four adapters): float/`Money` → `Decimal`. Needs a consumer audit
  (anything doing float math on `Balance.*`).
- `Order` reads (binance/mexc/phemex `get_open_orders`): only after Decision 1 (DTO
  extension) and a consumer audit of `Order.price` float→`Money`.

**MUST NOT TOUCH YET**
- `Position` sites (bingx/phemex): last — depend on Decision 4 currency policy and the
  explicit latent-bug correction; phemex change is type-correcting (str→enum, float→`Money`).
- Any domain-entity `__post_init__` coercion — deferred (Decision 3).
- Domain→domain reconstructions (`bingx temp_order`, `multi_broker enhanced_order`) — not
  raw→domain boundaries; leave as-is.

## Updated safe migration order (foundational → riskiest)
1. **Decision 2:** enhance `to_symbol()` normalization (separator strip) — foundational; parity-check (esp. bingx, ingestion output unaffected).
2. **Decision 1:** extend `OrderDTO` + `order_to_domain()` (stop_price/stop_loss/take_profit/time_in_force/position_side). Domain untouched.
3. `broker_manager.py` — confirm no-op.
4. `multi_broker_service` symbol-validation sites → `to_symbol()`.
5. `Balance` sites → `balance_to_domain()` (Decimal), after consumer audit.
6. `Order` reads → `order_to_domain()` (now complete), after `Order.price` consumer audit.
7. `Position` sites → `position_to_domain()` (currency via `quote_asset()`), last; corrects phemex/bingx latent bugs.

Each step: parity/behavior-delta check + STOP for review before the next.
