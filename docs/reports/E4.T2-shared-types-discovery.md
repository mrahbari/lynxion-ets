## 1. Why E4.T2 is blocked

`shared/types.py` is **not enum-only**. It is a full **shadow model**: it redefines
`Signal / Order / Fill / Position / Balance / MarketData` using **primitive types**
(`str`, `float`) that are structurally **incompatible** with the canonical
`domain.entities` versions (which use value objects `Symbol` / `Money` / `Percentage`
/ `Decimal` and enforce `__post_init__` invariants). It also defines an **`OrderType`**
enum that has **no home in `domain`** and is **not** in the task's canonicalization
list. Therefore a *mechanical, no-behavior-change* "repoint to domain + delete" is not
possible without scope expansion (add `OrderType` to domain, or decommission the dead
consumer cluster) — both RULE-1 violations.

**Decisive liveness fact:** `shared.types` has **no live functional consumer**.
- The live container wires the *flat* `infrastructure/**/*_adapters.py` files
  (`backtest_adapters.py`, `portfolio_adapters.py`, `strategy_adapters.py`, …), which
  are already on `domain.entities`.
- All `shared.types` importers are the **dead `infrastructure/*/adapters/` parallel
  subtree** plus the dead `application/backtesting/backtest_engine.py`.
- The only **live-reachable** importer is `infrastructure/backtest/adapters/walk_forward.py`
  (reached via container `wfo_orchestrator_factory` → `application/walk_forward/wfo_orchestrator.py:14`),
  and its `from shared.types import Signal, Order` is a **dead import** — neither name
  is referenced in the file body (it operates on pandas DataFrames / dicts and
  `RealisticBacktester`).
- **No test** (local `tests/`) imports `shared.types` or any dead-cluster module.

Net: deleting `shared/types.py` today breaks only **already-dead** modules' import
lines; the suite would stay green. The block is *architectural hygiene* (don't leave a
cluster of files with dangling imports), not a runtime dependency.

## 3. `OrderType` — focused analysis

- **Values:** `MARKET`, `LIMIT`, `STOP`, `OCO`.
- **Ownership layer:** *domain* concept (the kind/type of an order is a trading-domain
  notion, peer to `OrderSide`). It is **not** an infra-only concern. However, the
  canonical domain currently models order type as a **plain `str`** on
  `domain.entities.Order.order_type` (values "MARKET"/"LIMIT"), with helpers
  `is_market_order()` / `is_limit_order()`. So domain has deliberately *not* promoted
  this to an enum.
- **Live consumers:** **NONE.** All 4 importers are in the dead subtree:
  `infrastructure/execution/adapters/{executor,vwap,twap}.py` and
  `infrastructure/strategies/adapters/base_strategy.py`. None is reachable from the
  live container, any entrypoint, or any test.
- **Recommended canonical home:** **Do nothing now** (per user instruction — do not add
  `OrderType` to domain). If a *future live* need arises, the canonical home is
  `domain/enums/order_type.py` (mirroring `order_side.py`), and `Order.order_type`
  could be migrated `str → OrderType` as a separate, explicitly-scoped task. Until a
  live consumer exists, promoting it is speculative and out of scope.

consumer is a semantic rewrite, **not** a mechanical import swap. The pragmatic path is
deletion (§5), not migration.
