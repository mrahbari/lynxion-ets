## 0. EXECUTIVE SUMMARY

Unlike the engine layer (E3.T7, where the canonical thing was dead), the backtest layer
**already has a singular, golden-tested truth source**: `RealisticBacktester`
(`infrastructure/backtest/realistic_backtester.py`). The fragmentation is in the *periphery*:

- **1 canonical engine** — `RealisticBacktester` — wired live and pinned by two golden tests.
- **1 active portfolio wrapper** — `ComprehensivePortfolioBacktester` — delegates per-symbol to the canonical engine.
- **1 legacy "shadow" stack** — `BasicBacktestEngineAdapter` (+ mock data) behind `BacktestEnginePort` — reachable from a *different* CLI, uses mock data, no fees/slippage/SL-TP, **not golden-tested**. This is the one **conflicting truth source**.
- **4 fully dead engines** — `real_backtest_engine.py`, `realistic_backtest_engine.py`, `application/backtesting/backtest_engine.py`, `adapters/simulator.py` — zero importers; each reimplements PnL/fees/equity differently.
- **The existing `BacktestEnginePort` abstracts the WRONG engine.** Its signature
  `run_backtest(symbol, start_date, end_date, initial_capital)` matches only the legacy+dead engines.
  The canonical `RealisticBacktester.run_backtest(data, strategy_function, strategy_params)` **does not implement the port.** (Exactly the T7 pattern: the port describes dead code, not the live truth.)

**Bottom line:** Consolidation is *safe to proceed* as a T7.1-style move — define a canonical
backtest port **around `RealisticBacktester`**, add a thin adapter, wire additively, deprecate the
legacy/dead periphery (deletion deferred to E8). One decision gate remains: the fate of the legacy
mock-data stack. **No deeper redesign of the engine is required.**

## 2. LIVE vs BACKTEST GAP ANALYSIS

| Question | Finding |
|---|---|
| Does backtest mirror the live pipeline? | **No.** Live = `Watcher → EngineService.process_observation → Fusion → Strategy → Risk → Broker`. Backtest = `DataFrame → injected strategy_function(row, params) → RealisticBacktester (own exec sim)`. |
| Are signals identical? | **No.** Backtest signals come from a standalone `strategy_function` (e.g. close-vs-SMA in the golden test). The live `EngineService`/Fusion/Strategy chain is **not** exercised. |
| Are risk rules identical? | **No.** Backtest risk = the backtester's *own* ATR-based SL/TP + `max_drawdown=0.90` kill (`realistic_backtester.py`). The live consolidated risk engine (`ConsolidatedRiskEngineAdapter`, E3.T4) is **not** used in backtest. |
| Is execution simulation realistic? | **Canonical (#1): yes** — fees (`trade_value*fee_rate`), slippage (`slippage_factor*price`), market impact (`*(1+2*ratio)`), candle-based SL/TP fills. **Legacy (#3): no** — fixed 10% sizing, no fees, no slippage, no SL/TP. |

**Divergence summary:** the backtest layer is *decoupled from the live signal/risk pipeline by design*
(strategy functions are injected). This is a **strategy-research harness**, not a replay of production.
That is acceptable for E3.T1 (we are consolidating the *engine*, not unifying it with live) — but it
means "backtest == live" parity is **not** a goal that can be asserted today, and should be called out.

## 4. TRUTH SOURCE ANALYSIS

- **Source of truth:** `RealisticBacktester` (#1). It is what `tests/e2e/test_backtest_golden.py` pins (scalar metrics on a committed OHLCV fixture, seeded RNG) and what `tests/e2e/test_backtest_cli_pilot.py` asserts is byte-identical across the container-wired vs legacy-runner path (both resolve to #1 via `backtester_factory`).
- **Is there more than one?** Effectively **two reachable**: #1 (canonical) and #3 (legacy mock stack behind `BacktestEnginePort`, via `trading_system_modes`). #2 is not a separate truth — it *wraps* #1.
- **Which is trusted by tests?** Only **#1** (and #2 transitively). **#3 has no golden test** and runs on **mock data** → it is a latent *conflicting* truth source that could report different numbers than #1 for the "same" backtest.

## 5. ARCHITECTURE DIAGNOSIS

| Symptom | Verdict |
|---|---|
| ❗ Fragmented | **YES** — 7 engine implementations exist; 4 dead, 1 legacy, 1 canonical, 1 wrapper. |
| ❗ Partially unified | **YES** — canonical #1 is already shared by runners/optimizers/portfolio/WFO. |
| ❗ Conflicting truth sources | **YES (one)** — legacy `BasicBacktestEngineAdapter` (mock, untested) is reachable alongside #1. |
| ❗ Hidden coupling to live engine | **NO (inverted)** — backtest is *decoupled* from the live signal/risk pipeline (injected strategy fns). The gap is *too little* alignment, not hidden coupling. |
| ❗ Missing abstraction layer | **YES** — the canonical engine #1 has **no port**; the existing `BacktestEnginePort` abstracts the legacy/dead engines (wrong signature). |

Plus two **naming hazards**: two classes named `RealisticBacktestEngine` (#4, #5); two classes named `RunBacktestUseCase` (`run_backtest.py` live vs `backtest_use_cases.py` legacy); `RealisticBacktester` vs `RealisticBacktestEngine` are easily confused.

## 6. SAFE CONSOLIDATION PLAN (NO CODE — structural only, ≤8 steps)

> All steps are additive/documentary. No deletion (E8). No engine-logic refactor.

1. **Pin the portfolio wrapper.** *Goal:* add a golden fixture for `ComprehensivePortfolioBacktester` (single-asset golden already covers #1). *Risk:* **low.** *Deps:* tests only. *Safe:* read-only characterization; no production code touched.
2. **Define canonical `BacktestPort` around #1's REAL contract** (`run_backtest(data, strategy_function, strategy_params) -> Dict`). *Goal:* a port that matches the truth source. *Risk:* **low.** *Deps:* `domain/ports/`. *Safe:* new Protocol, no implementer forced; existing `BacktestEnginePort` left untouched.
3. **Thin adapter wrapping `RealisticBacktester` behind the new port** (pure delegation, mirrors `EngineServiceAdapter`). *Risk:* **low.** *Deps:* `infrastructure/backtest/`. *Safe:* delegation only, byte-for-byte; golden test #1 proves no drift.
4. **Additive container registration** (`register("backtest_engine", …)` resolving the adapter over the existing `backtester_factory`). *Goal:* container resolves the canonical engine via the port. *Risk:* **low.** *Deps:* `bootstrap/container.py`. *Safe:* additive; `backtester`/`backtester_factory` and all live consumers unchanged.
5. **Decision gate on the legacy stack** (`BasicBacktestEngineAdapter` + `BacktestEnginePort` + mock data). *Goal:* decide redefine-vs-keep (see §7). *Risk:* **low** (planning). *Deps:* none. *Safe:* no code; resolves the one conflicting truth source on paper before touching it.
6. **Deprecate (docstring-only) the dead engines** (#4, #5, #6, #7, #10) and the legacy stack, pointing to the canonical engine. *Goal:* signal intent; block accidental reuse. *Risk:* **low.** *Deps:* docstrings only. *Safe:* no behavior change (identical to the E3.T7.1 deprecation pattern); physical removal deferred to E8.
7. **Disambiguate naming in docs/banners** (note the two `RealisticBacktestEngine` and two `RunBacktestUseCase`). *Goal:* prevent wrong-import hazards during migration. *Risk:* **low.** *Deps:* docstrings/report. *Safe:* documentation only.
8. **Record E8 backlog** (physical deletion of #4–#7, #10; collapse legacy `RunBacktestUseCase`; retire `BacktestEnginePort` if the legacy stack is dropped). *Goal:* hand off cleanup. *Risk:* **none.** *Deps:* backlog doc. *Safe:* no code.

## 6a. PHASE-0 DECISION (RATIFIED)

> **DECISION (architecture ownership): Option A — Retire & Redefine; legacy mock stack = deprecate-only.**
> - `RealisticBacktester` is the **sole canonical** backtest engine.
> - `BacktestEnginePort` is **redefined** (not extended) around its real contract
>   `run_backtest(data, strategy_function, strategy_params) -> Dict`.
> - `BasicBacktestEngineAdapter` + `MockHistoricalDataProviderAdapter` + the legacy
>   `backtest_use_cases.RunBacktestUseCase` are **deprecated (docstring-only)**; left reachable as-is for
>   now; **no** official "mock mode" CLI surface is added; physical removal deferred to **E8**.
> - Golden tests (`test_backtest_golden.py`, `test_backtest_cli_pilot.py`) remain the truth source.
> - Options B (dual-mode) and C (full migration) rejected.
> Implementation is a SEPARATE step (E3.T1 Phase 1) — out of scope for this decision gate.

## 7. FINAL DECISION FOR NEXT PHASE

👉 **It IS safe to proceed to E3.T1 implementation** as a T7.1-style consolidation
(canonical `BacktestPort` around `RealisticBacktester` + thin delegating adapter + additive container
wiring + docstring-deprecation of dead/legacy modules). Justification: the truth source is **already
singular and golden-tested**, the canonical engine is internally consistent, and all duplication lives
in **dead/legacy** code that the plan retires without merging live logic.

👉 **No deeper redesign of the backtest engine is required.** The only open question is a **decision
gate** (Plan step 5), exactly mirroring E3.T7.1 Option A:
- **Recommended:** redefine the canonical contract around `RealisticBacktester` and **deprecate** the
  legacy `BasicBacktestEngineAdapter` + mock stack (and the mismatched `BacktestEnginePort`), with
  physical removal deferred to E8.
- **Alternative:** keep the legacy stack as a separate, documented "mock/smoke" path — only if some CLI
  mode genuinely needs a network-free mock backtest.

**Caveat to surface, not fix here:** backtest does **not** replay the live signal/risk pipeline
(strategy functions are injected; live `EngineService`/`ConsolidatedRiskEngineAdapter` are bypassed).
That is out of scope for E3.T1 (engine consolidation) but should be logged as a separate
backtest-vs-live *parity* concern for a future epic.
