## 3. Proposed `application/dto/` structure (design only — no code)

Sits at the application/infra boundary; converts raw external shapes → domain VOs/entities.
Construction of `Symbol`/`Money`/`Percentage` happens **here** (the edge); everything inward
is typed with VOs/entities.

```
application/dto/
  __init__.py
  market_data_dto.py   # MarketDataDTO(symbol:str, open/high/low/close/volume:float, ts:int)
                       #   .to_domain() -> MarketData  (builds Symbol(...), Decimal(...))
                       #   .from_row(dict)/from_ohlcv(...) inbound builders for B1/B2/B3
  order_dto.py         # OrderRequestDTO / OrderResultDTO  <-> Order / Fill
                       #   exchange response dict/float -> Order/Fill with Money/Decimal (B5/B6)
  balance_dto.py       # BalanceDTO(asset:str, total/available/reserved:float)
                       #   .to_domain() -> Balance (Decimal) ; Money via asset (B4/B6)
  position_dto.py      # PositionDTO  <-> Position (Money entry_price, Decimal qty) (B4/B6)
  mappers.py           # pure edge constructors with validation:
                       #   to_symbol(str)->Symbol ; to_money(x,ccy)->Money(Decimal(str(x)),ccy)
                       #   to_percentage(x)->Percentage ; raises on invalid raw input
```

**Design principles (aligned to the task constraint):**
- DTOs are plain primitive-typed carriers (mirroring external/exchange shapes) — the *only*
  place raw `str`/`float`/`dict` is allowed.
- `.to_domain()` / `mappers.py` are the single choke points that build VOs, so invalid raw
  inputs are rejected at the edge (satisfies "boundary test rejects invalid raw inputs").
- Domain & application interiors consume **entities/VOs only**.
- Tabular pandas stays in infra (E4.T3); DTOs convert DataFrame rows → `MarketData` at the
  boundary, never exposing pandas inward.
- **No DTO mirrors `shared.types`** — DTOs map *live* exchange/CSV shapes to the *canonical*
  domain model; they do not assume or depend on `shared.types` being deleted.
