# E4.T4 — Live Broker/Execution Boundary Discovery (read-only)

Redefined Phase 2B (original targets deleted in E4.T2). Discovery ONLY — no code
changes, no wiring. Scope = the live broker boundary that constructs domain objects
from raw exchange payloads.

## 0. Cross-cutting fact (root cause of most risk)
`domain.entities` `Balance`/`Order`/`Position` have **no `__post_init__` coercion** —
they store whatever type is passed. The live adapters therefore pass **raw `float`/`str`/
`Money`** into fields typed `Decimal`/`Money`/`PositionSide`. The mappers
(`order_to_domain`/`balance_to_domain`/`position_to_domain`) **enforce** canonical types
(`Decimal`/`Money`/enum/`Symbol`). So virtually every migration is a **stored-type change**,
even when the numeric value is equal — that is the core trading-correctness risk.

Also: **the DTO/mapper contract is narrower than the live Order**. `OrderDTO` has **no
`stop_price` and no `time_in_force`** fields, and `order_to_domain` builds `price` as
`Money` (adapters use `float`). Migrating Order reads as-is would **drop `stop_price`/
`time_in_force`** and **change `price` type**.

## 2. Current transformation logic
- **Symbol normalization:** binance/mexc/phemex → `Symbol(item['symbol'])` raw (exchange format, already upper, no dash). **bingx → strips dashes** (`replace("-","")`). multi_broker → `DomainSymbol(symbol)` with **no** normalization. *Outbound* formatting handled separately by `SymbolFormatHelper`.
- **Currency:** binance/mexc/phemex Balance — **no currency** (plain numeric fields). bingx Balance — `Money(currency=asset)`. bingx Position — **hardcoded `'USDT'`**. phemex Position — **none** (raw float).
- **Numeric parsing:** universally `float(...)`; phemex scales `/100000000.0` (8-dp). Stored as float (Balance/Order) or wrapped in `Money` (bingx) — never `Decimal`.
- **Timestamp:** binance/mexc/phemex Balance/Order → `datetime.now()`; bingx Position → `datetime.fromtimestamp(time/1000)`; phemex Position → `datetime.now()`.

## 4. Risk classification

**SAFE (no behavioral change)**
- `broker_manager.py` — nothing to migrate (delegator).
- Out-of-scope reconstructions (`bingx temp_order`, `multi_broker enhanced_order`) — domain→domain, leave as-is.

**UNSAFE (behavior will change)**
- **All `Balance` sites** (binance/bingx/mexc/phemex): float/`Money` → `Decimal`; binance asset-casing lost; bingx loses `Money` currency. Stored type changes.
- **All `Order` reads** (binance/mexc/phemex `get_open_orders`): `price` float→`Money`, `quantity` float→`Decimal`, and **`stop_price`/`time_in_force` dropped** (not in `OrderDTO`).
- **`bingx._parse_symbol`**: dash-strip lost → **different Symbol value** → position/order symbol mismatch.
- **`phemex` Position**: str side→enum, float→`Money` (changes a latently-broken construction).

**UNKNOWN (needs clarification)**
- **Currency source** for `order_to_domain` price and `balance_to_domain`/position Money: adapters mostly omit currency or hardcode `'USDT'`. What currency should the mapper use per exchange/payload?
- **DTO completeness**: should `OrderDTO`/`order_to_domain` gain `stop_price`/`time_in_force` (a contract extension) so Order reads don't lose risk params? (Currently out of "no new DTOs" scope.)
- **`Money` vs `Decimal` for Balance**: entity field is `Decimal`; bingx uses `Money`. Which is canonical?
- **multi_broker `DomainSymbol`**: is `to_symbol`'s upper/strip normalization acceptable (changes lowercase-symbol handling)?
- **Latent bugs**: bingx Position `quantity=float` breaks `calculate_unrealized_pnl` (Decimal×float `TypeError`); phemex Position str-side/float-price. Migration would "fix" these — is that desired now, or preserve current (broken) behavior?

## 5. Behavioral differences (summary)
1. Stored numeric type float→`Decimal` across all Balance/Order/Position numeric fields.
2. `Order.price` float→`Money` (type change visible to any consumer).
3. `Order.stop_price` + `time_in_force` **lost** on reads (DTO gap).
4. `Balance.total/available/reserved`: bingx `Money`→`Decimal`; binance `asset.upper()` dropped.
5. bingx symbol: dash-strip lost.
6. phemex Position: `side` str→enum, prices float→`Money` (type correction).

## 6. Recommended migration order (safe → unsafe)
1. **`broker_manager.py`** — no-op (confirm only).
2. **`multi_broker_service.py` Symbol-validation sites** (:211/:280/:728) — route `DomainSymbol(symbol)` → `to_symbol()`; smallest surface (resolve the lowercase-normalization UNKNOWN first).
3. **Balance sites** — after deciding Decimal-vs-Money + asset-casing; uniform float→Decimal.
4. **Order reads** — only after extending the DTO/mapper to carry `stop_price`/`time_in_force` and deciding price `Money`/currency. (Contract change required.)
5. **Position sites** — last; resolve currency + the phemex/bingx latent-bug decision.

## 7. Critical trading risks
- **Risk-param loss:** migrating Order reads through current `OrderDTO` **silently drops `stop_price`/`time_in_force`** → SL/stop orders mis-represented. **Hard blocker** until DTO extended.
- **Price type flip:** `Order.price`/Balance numerics changing float→`Money`/`Decimal` can break any consumer doing float arithmetic/serialization on them (or fix consumers expecting Money) — must audit consumers first.
- **Symbol identity (bingx):** losing dash-strip changes the Symbol used for position/order matching → could mis-route or fail lookups on a live futures broker.
- **P&L math:** float vs `Decimal` quantity interacts with `Money.amount` (`Decimal`) in `calculate_unrealized_pnl` — current bingx path is latently broken (Decimal×float); any change here alters live P&L behavior.
- **Currency correctness:** hardcoded/absent currency means `Money` construction may attach the wrong currency if mapper defaults to `"USD"`.

**Conclusion:** none of the broker boundary is SAFE-to-migrate as-is except the `multi_broker` symbol-validation sites (pending one normalization decision) and the no-op delegator. The rest requires (a) a DTO/mapper contract extension for Order, (b) Decimal-vs-Money + currency decisions for Balance/Position, and (c) a consumer audit — before any wiring.

Discovery only — no code changes, no wiring.
