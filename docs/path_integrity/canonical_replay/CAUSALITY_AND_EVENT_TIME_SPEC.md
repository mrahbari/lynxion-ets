# Point-in-time contract and observed gaps

`ClosedBar` uses UTC-aware `[open_time, close_time]` with `close_time = open_time + timeframe`. A decision at T sees only bars whose `close_time <= T`; equal-close MTF bars are available only after that close. Source order is nondecreasing close time. Per `(symbol,timeframe)`, duplicate/out-of-order closes and gaps/overlap are rejected, never filled. OHLCV must be finite/valid; missing values are rejected, not turned into zero. The source never calculates indicators, normalizers, regime thresholds or watcher observations, so it cannot perform bfill or future-derived warmup.

This contract is **not yet enforced end-to-end**. Live `SignalEvent` can default its timestamp to wall clock; `HistoricalCandleWatcherAdapter` stores a wall-clock fallback for missing input timestamp and sets output observation timestamp to `datetime.now()`. `SignalAggregator` uses wall-clock aggregation and a new thread; its intent correlation ID uses wall time. Auto-detection execution/cooldown also contains wall-clock decisions. These are `WALL_CLOCK_NONDETERMINISTIC` for replay until a minimal shared event clock and isolated synchronous scheduling are proven. No production behavior was changed in this unit.

Prefix invariance at the source does not establish indicator/strategy/Fusion prefix invariance. Such a claim requires a future full-pipeline test, including warmup NaN, UTC/day transition, MTF closure, same-bar high/low and state reset. Candle high/low must not be visible before its close; exit-fill high/low priority is outside this unit.
