## Acquisition specification — proposal only, requires separate dataset binding

This specification is written before viewing any study outcomes; **do not execute it under this unit**. The repository already contains a potential acquisition pattern in `scripts/fetch_microstructure.py`: Binance USD-M futures `GET /fapi/v1/klines`. Choose **one** source/exchange for both BTCUSDT and ETHUSDT, not a patchwork of the unknown processed files. Before acquisition, retain source/API documentation proving response fields `k[0]` (interval open time) and `k[6]` (reported close time), interval inclusion/closure rules and UTC epoch-millisecond units; the repository script alone does not prove the semantics of a particular future capture. Preserve raw response fields, not only the reduced CSV.

- Fixed neutral request interval for a **new** cohort: `2026-06-01 00:00 UTC` inclusive to `2026-07-01 00:00 UTC` exclusive, both symbols, 1h. This 30-day common interval is within the old cap and gives ~720 hourly bars per symbol: 50-bar warmup + 20 calendar days + four-bar label horizon plus >7 days' calendar safety margin. It does **not** guarantee 100 eligible directional events; that remains a post-path sample-size check, never a reason to change the interval after inspecting outcomes.
- Require complete OHLCV (`open_time_ms`, `close_time_ms`, open/high/low/close/volume), exchange symbol, interval and preferably exchange finality indicator if provided. Store UTC original integers and immutable raw page responses at a **new** versioned location such as `data/research/pre_intent/candle_capture_v1/raw/{symbol}/{page_id}.json`; never overwrite the existing frozen CSVs. Do not transform timestamps into floating point. For each page store request URL/path and nonsecret parameters, response status, UTC request/receipt times, source/API version/documentation reference, pagination cursors, page count and SHA-256. No credential-bearing material in the manifest.
- A separate normalized, immutable closed-bar artifact may be proposed only after raw capture audit: one row per symbol and hour with both raw open and close timestamps; visibility time must be **no earlier than confirmed completion**, e.g. the next hour boundary for exchange inclusive close timestamps. Verify source close semantics and `close_time <= decision_time` explicitly. Fail on duplicate, nonmonotonic, missing, overlapping, malformed/nonfinite/negative-volume/impossible OHLC or incomplete last bar; record all defects, no silent repair. Do not mix endpoints/exchanges. Hash raw and normalized files and freeze a manifest before any prefix test or outcome study.

It requires a separately reviewed, pre-outcome dataset-binding addendum/new preregistration that changes only data identity (not symbols, timeframe, outcomes, thresholds or hypothesis), with its own hash/commit, before qualification or study use. No such amendment is made here.
