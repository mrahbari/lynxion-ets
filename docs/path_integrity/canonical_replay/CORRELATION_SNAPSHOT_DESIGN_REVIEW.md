# Correlation snapshot design review

Starting HEAD: `35b5c4e`. This review separates partial-state visibility from worker scheduling. Existing Risk formula, thresholds, 100-price window, five-sample minimum, 10-second wall-clock loop and sizing formula are immutable in this unit.

## Source finding

`recalculate_correlations()` builds a new nested dictionary under `correlation_lock` and publishes it with one `self.correlation_matrix = new_matrix` assignment. It does not mutate the published dictionary afterward. `record_price()` uses the lock, but `calculate_correlation_penalty()` does not. It reads `self.correlation_matrix` inside the loop for each portfolio symbol, so a multi-position sizing decision can combine cells from different published matrices if the worker runs between iterations. Even for one other symbol, the matrix used depends on worker/sizing interleaving. Neither published matrix version nor publication timestamp nor price-source cutoff is recorded. The price history stores values, not their event timestamps.

The existing observable runtime rule is approximately **"use whatever published matrix cell is visible when each penalty lookup occurs"**, not provably "use one snapshot available when sizing begins". A publication timestamp/version would formalize a *new* single-snapshot rule. The worker is periodic relative to construction and its previous computation, not event time; its wake-ups and tie order with price/sizing are not recorded. Thus `LIVE_RUNTIME_SEMANTICS_DEFINED` only at this weaker interleaving level; `HISTORICAL_EXACT_SCHEDULE_NOT_RECONSTRUCTABLE` from current archives. Prospective snapshot recording could reproduce a particular observed Live run, not prove deterministic live policy or reconstruct prior history.

No design satisfies all five autonomous implementation criteria simultaneously without a potential economic ordering change. Correlation branch remains parked as `CORRELATION_PARITY_BLOCKED_BY_LIVE_CONCURRENCY`. The minimal operator decision is whether to authorize a common serialized ordering and scheduler anchor for Live and replay, with controlled evidence that any quantity change is acceptable. An atomic snapshot alone must never be presented as solving the scheduling issue.
