# Narrow persistence and execution-state ports — design only

The [Unit-3 persistence matrix](REPLAY_PERSISTENCE_BOUNDARY_MATRIX.csv) identified live defaults. Source recheck adds `MultiBrokerExecutionService` importing global `live_order_journal` and `live_execution_guard`, `BrokerExecutionService` using class-level `PendingOrdersTracker`, `BrokerReconciliationService` fixed `ACTIVE_POSITIONS_JOURNAL_PATH`, and `LiveExecutionGuard` using a global circuit-breaker manager and default execution-truth ledger. A simulated broker cannot make these safe by itself. A full replay must fail construction if any live path/credentialed adapter is reachable.

| Resource | Classification | Minimum semantic port / live adapter / replay adapter |
|---|---|
| Cooldown state and loss history | NEEDS_NARROW_PORT | `CooldownStateStore`: load/save expiry and loss history by normalized symbol. Live adapter retains today's atomic JSON and trade-journal reconciliation semantics; replay adapter begins empty or from explicitly supplied *pre-run* state, in memory. No current trade journal import. |
| RiskEnforcement cooldown map | NEEDS_NARROW_PORT | Use the **same** scoped cooldown store/gate as queue and guard; remove fixed `COOLDOWN_JOURNAL_PATH` from replay construction. Live adapter preserves exact path and policy. |
| Active-position transitions | NEEDS_NARROW_PORT | `ActivePositionStore`: snapshot/update active symbols and closure identity. Live adapter wraps current atomic journal; replay adapter in memory. Canonical position veto must use scoped broker/portfolio view, not merely a journal flag. |
| Order lifecycle/recovery | NEEDS_NARROW_PORT | `OrderStateStore`: intent/submitted/terminal records and lookup by order/client ID. Live adapter wraps `LiveOrderJournal`; replay adapter in memory. No replay broker registry or live recovery call. |
| Pending-order duplicate state | NEEDS_NARROW_PORT | `PendingOrderTracker` instance interface mirroring existing add/remove/query and expiry; live adapter delegates class tracker until migrated; replay owns fresh map with event clock. |
| Logical-intent claims | NEEDS_NARROW_PORT | `IntentClaimStore`: atomic claim by opaque logical ID within run; live adapter preserves current process semantics; replay in-memory instance. Durability/retry after process restart is **not** solved here. |
| Portfolio/risk positions and daily PnL | ALREADY_PORTED_PARTIALLY | `ConsolidatedRiskEngineAdapter` wraps one `EnterpriseRiskManager`; compose a new manager per replay and pass it both to price recorder and `RiskEnforcement`. Audit any remaining global container lookup before release. |
| Guard kill switch and circuit breaker | NEEDS_NARROW_PORT | One scoped `LiveExecutionGuard` plus breaker store; live default unchanged, replay receives fresh state. Do not bypass guard because broker is simulated. |
| Execution-truth/forensic logging | NEEDS_NARROW_PORT | Narrow trace sink with live append-only implementation and replay in-memory implementation; decision errors still surface. No shared file handle/path. |
| BrokerReconciliationService loop | LIVE_ONLY for scheduling; shared reconciliation **policy** where tested | No live poll loop in replay. Later simulated broker/order store must expose equivalent state transitions for an explicit deterministic reconciliation step; do not omit active-position protection. |
| Credentials/live broker adapters | NOT_REACHED_BY_REPLAY by construction | Replay execution port type has no credential settings, HTTP client or `broker_registry`; reject an instance carrying a live adapter before starting. |

These are **semantic interfaces**, not a generic repository abstraction. They may be expressed as small protocols around existing methods; do not create one new service per row if existing adapters can share a focused interface safely. Count/budget in implementation sequence assumes approximately five narrow ports (price/forensic, cooldown, position/order state, claim/pending, guard/breaker) with 3–5 in-memory adapters; exact count is provisional pending focused call-site audit. Each live adapter must preserve existing fsync/recovery behavior. In-memory replay stores are never hydrated from live paths by default. File-path overrides alone are insufficient when module globals have already loaded live state.

Boundary tests must deny reads **and** writes to `data/active_positions_journal.json`, `data/sl_cooldown_journal.json`, `data/trade_journal.csv`, `data/live_order_journal.json` and the execution ledger, then construct and exercise two replay scopes. Hash those files before/after as a second independent check. Do not delete/reset any production file. Broker timeout/restart reconciliation remains `BROKER_RETRY_SEMANTICS_UNRESOLVED` and is not implied by an in-memory replay store.
