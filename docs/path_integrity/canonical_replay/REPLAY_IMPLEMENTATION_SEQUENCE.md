# Bounded implementation sequence — not authorized by this review

Each unit is independently committable, keeps live defaults, and stops if a normalized live fixture changes unexpectedly. The sequence is ordered so no replay context is constructed while a production persistence/global dependency is still reachable. Unit 1/2 replay primitives already exist; this plan does not redo them. Tests use network-incapable ports and no economic data.

The XMR generic invariant belongs in E/F tests **after** isolation, not before: one eligible logical intent → at most one pre-broker attempt; when canonical position is active, later same-symbol conflicting/duplicate intents obey unchanged position/cooldown policy. Repeat with non-XMR symbol to rule out fixture special-casing. Do not remove XMR blacklist/blocker automatically.

Estimated surface: **LARGE but staged**, not a one-commit rewrite: approximately 18–28 existing production files across seven units, ~5 narrow interfaces/protocols (some may reuse existing ports), 3–5 in-memory adapters, two composition entry points (live compatibility and replay), and 10–16 focused test files. Actual counts must be revised after unit A–E call-site inventories; this is not a LOC commitment. The breadth comes from verified globals in multiple layers, not architecture embellishment. No profitability/research work is part of these units.

Release gate order: A–E must close global/persistence/time seams and preserve live behavior; F proves two concurrent scopes and no production access/network capability; only G may attempt full decision prefix invariance or live/replay parity. If any unit needs a strategy/Fusion/risk policy change or a new execution owner, stop for review. A later economic baseline requires separate authorization after all applicable gates pass.
