# Canonical path integrity — remediation design only

**Scope/status:** source-level trace at HEAD `5854053` (2026-09-23). No runtime, broker, backtest, strategy, configuration, or cohort was changed or run for this design. This specifies parity gates, not a claim that parity already exists. The production `--auto-detect` route is the relevant live entry; separate legacy/function-based backtests remain noncanonical unless explicitly retired from performance claims.

## A. LIVE_CALL_GRAPH

`AutoDetectionOrchestrator.__init__` starts `ArchitectureOrchestrator` and `MarketOpportunityWatcher` (`infrastructure/orchestrators/auto_detection_orchestrator.py:56-82`). Watcher adapters produce `MarketObservation`; `MonitoringAnalysisService` publishes it to the event router (`infrastructure/watchers/monitoring_analysis_service.py:441`). `SignalProcessor` handles observation → `EngineService.process_observation` → interpreted-signal event → `FusionService.fuse_signals([signal])` → fused-signal event (`infrastructure/messaging/event_system.py:150-264`). The single-item Fusion invocation is the *observed* event wiring; do not assume multiple watcher signals are combined in one call. `SignalAggregator` collects/ranks/selects fused signals, then calls `StrategyManager.evaluate_fused_signal` (`infrastructure/aggregators/signal_aggregator.py:60-157,197-265`). The manager evaluates all registered adapters' `evaluate_fused_signal`, scores/ranks intents, returns one (`infrastructure/strategies/strategy_manager.py:539-589`). The aggregator publishes that `ExecutionIntent`.

Downstream there are **two subscribers/routes**, not one proven unique route: `SignalProcessor._process_execution_intent` converts intent to order, uses the risk engine for dynamic size, sanitizes SL/TP, caps notional and calls `execution_service.execute_order` (`event_system.py:277-624`); auto-detection also subscribes to execution intents, queues and calls `_execute_trade_from_intent`, with its own duplicate/cooldown, sizing and order construction (`auto_detection_orchestrator.py:71,430-486`; `_auto_detection_execution.py:33-357`). `BrokerExecutionService.execute_order` applies symbol/duplicate/SLTP validation and `LiveExecutionGuard.authorize_and_send` before broker send (`infrastructure/services/broker_execution_service.py:197-355`). Auto-detection's periodic broker reconciliation is separate (`auto_detection_orchestrator.py:620-665`); journals/ledger are written in execution components. **Which of the two intent subscribers acts for a particular live event, and whether both can, requires a deterministic trace before declaring a single canonical execution path.** Source registration alone is insufficient proof of exactly-once behavior.

## B. BACKTEST_CALL_GRAPH

`RunBacktestUseCase` → `_run_backtest_process` loads historical frames, date-filters, computes shifted features, then `df.ffill().bfill().fillna(0)` (`application/use_cases/run_backtest.py:260-301,410-456`). It requests one named strategy from `BacktestStrategyProvider` (`infrastructure/backtest/strategy_provider.py:740-745`). Per row, that provider updates one adapter's bar buffer → `adapter.generate_signal()` → derives direction/confidence → builds a **mock** `FusedSignal` (regime defaults to strategy name) → calls the same adapter's `evaluate_fused_signal` (`strategy_provider.py:15-133`). The wrapper returns this intent or, for function-only strategies, creates another intent with fixed percentage size and ATR geometry (`strategy_provider.py:651-735`). `RealisticBacktester.run_backtest` calculates another indicator set, walks rows, adapts domain intent into infrastructure intent with its own sizing/SLTP/risk checks, then executes simulated fills/exits (`infrastructure/backtest/realistic_backtester.py:852-985,1427-1605,1804-1864`). There is no observed Watcher → Engine → real Fusion → SignalAggregator → StrategyManager → live order/guard route in this runner. Backtest's simulated fills and cost model are separate execution semantics, not a broker-port substitution on the same upstream pipeline.

## C. DIVERGENCE_MAP

| Boundary | Live/auto-detect source path | Existing backtest | Verdict |
|---|---|---|---|
| Market event | Watcher emits `MarketObservation` | Historical row to named adapter | **First divergence**: no equivalent observation/event stream |
| Interpretation/Fusion | Engine interpretation, `FusionService.fuse_signals([signal])` | `generate_signal()` then strategy-derived mock `FusedSignal` | **Semantic divergence confirmed**; shared `evaluate_fused_signal` is downstream only |
| Selection | Aggregator ranks fused events; manager evaluates/ranks all registered adapters | One requested adapter; no manager competition | Backtest-only selection/exclusivity |
| Intent/SLTP | Adapter intent then event or auto-detection order conversion | Adapter intent, wrapper fallback, domain→infrastructure conversion, backtester risk/SLTP | Duplicate transformations; no equality proof |
| Risk/guard/fill | Risk sizing/order validations and LiveExecutionGuard before broker; two intent subscribers to resolve | Backtester-specific cash, size, drawdown and fill checks | Not interchangeable; simulated broker alone is not sufficient |

Backtest-only decision logic includes named-strategy selection, per-bar `generate_signal` veto, mock direction/regime/confidence, function-strategy fallbacks, wrapper percentage sizing/ATR SLTP, second indicator calculation, and backtester-specific risk/fill acceptance. Live-only decision logic includes watcher admission/engine interpretation, real Fusion, cross-symbol aggregator ranking, manager competition/promotion scoring, event/auto-detection duplicate and cooldown gates, live order caps/guard, and broker reconciliation. Shared adapter `evaluate_fused_signal` does **not** erase these differences. Duplicated decision work is specifically mock versus real Fusion preparation, per-adapter versus manager strategy selection, wrapper/backtester versus adapter intent/SLTP/risk preparation, and event-system versus auto-detection order construction. This is a source trace, not measured equivalence.

## D. LOOKAHEAD_AUDIT

`calculate_indicators_with_shifting` constructs RSI, SMA, Bollinger, ATR, ROC, ADX, volume, extrema, VWAP-proxy and volatility/trend features from historical OHLCV (`run_backtest.py:43-128`). Most are shifted one row. `bid_ask_spread=(high-low)/close` is **unshifted**; it is safe only when a decision occurs after that candle closes, otherwise it exposes same-bar future information. Simulated MTF columns are rolling single-timeframe proxies, not validated cross-timeframe synchronization. The helper's derived columns and the original OHLCV columns then all undergo dataframe-wide `ffill().bfill()` (`run_backtest.py:430-439`):

| Operation/columns | Why present | Can t+n enter t? | Classification |
|---|---|---|---|
| Rolling/shifted indicators: `rsi`, `sma_*`, `bb_*`, `atr`, `roc_10`, `adx`, volume, high/low, `vwap`, volatility/trend columns | Warmup and invalid windows produce NaN | **Yes:** first valid later value can be backfilled to earlier warmup row | **LEAKAGE_CONFIRMED** for the transform; decision impact unmeasured |
| Original `open/high/low/close/volume`, if source contains gaps/NaNs | Historical data quality | **Yes:** whole-frame bfill can pull future observed price/volume backward | **LEAKAGE_CONFIRMED** if such gaps exist; occurrence in an accepted source file UNKNOWN |
| `ffill()` on a causally computed feature | Preserve most recent prior value | No by direction alone; stale/gap semantics still matter | **SAFE** only with event-time ordering, max-age and no future-built source value |
| Final `fillna(0)` on any remaining column | Avoid missing values | No future leakage, but zero can be a false market feature | **SAFE for future access; UNKNOWN for semantic validity** |
| `bid_ask_spread` of current bar and internal `calculate_indicators` in backtester (`realistic_backtester.py:1427-1467`) | Same-bar proxy / second feature pass | Depends on decision timestamp and bar-closure contract | **UNKNOWN** until closed-bar event timing is proven |
| Full-frame `classify_market_regime` quantiles (`run_backtest.py:130-165`) | Descriptive regime classification | Full-sample quantiles can incorporate future bars if applied to a decision | **UNKNOWN** decision influence; audit any call-site before reuse |

Causal alternative: reject incomplete/missing OHLCV and assert unique sorted completed-bar timestamps; compute indicators only from bars whose close time is `<= decision_time` (shift where the strategy consumes the next bar); preserve warmup NaN and mark the event ineligible until all required lookbacks are complete. A forward fill is permissible only for a predeclared maximum age after provenance checks. Never bfill or replace missing decision features with zero. Historical replay must emit only completed, point-in-time `MarketObservation`s. A prefix-invariance test below is a release gate.

## E. MINIMAL_REMEDIATION_PLAN

1. **Trace and select the existing live execution route before code change.** On an offline fixed event fixture, record subscriptions and call count from fused event to pre-broker order. If both intent subscribers can act, designate a single canonical handler as a separate approved correctness unit; keep execution guard/risk policies unchanged. This is a verified design dependency, not permission to silently remove a handler.
2. **Reuse the existing event pipeline for historical replay.** A historical market-data adapter must emit the *same typed completed-bar/observation events* into the existing router/Engine/Fusion/Aggregator/StrategyManager path, with deterministic event-time ordering and no wall-clock races. Do not manufacture a fused signal or call each adapter's raw generator as the canonical backtest. Supply a simulated execution service/broker port at the current orchestration boundary, preserving the shared pre-broker risk/order/guard decisions. Isolate broker-specific fills/fees after that boundary. If the current guard cannot represent simulation without live-config semantics, stop and review a narrow port seam rather than adding strategy-side mode conditionals.
3. **Causal feature admission.** Remove only the historical whole-frame backward/zero fill from the *new canonical replay path*; validate required lookbacks, data quality and close-time provenance before observations. Keep the old backtest clearly labeled legacy/noncanonical until parity tests pass. Do not use its PnL as strategy baseline. No strategy/default/Fusion/risk parameter change.
4. **Stage rollout:** deterministic dry-run trace → parity/prefix-invariance suite → execution-port simulation safety tests → only then separately authorize baseline measurement. Do not flip production routing in this design task.

## F. PARITY_TEST_PLAN

Use one frozen fixture of timestamped closed bars/observations (including BUY, SELL, HOLD, insufficient warmup, duplicate/gap and two competing symbols), one frozen settings snapshot, seeded/order-stable dependencies, identical initial portfolio/discipline state, and a broker spy incapable of network calls. Invoke the **same** application orchestration twice: historical replay source versus a live-source fixture adapter. Capture ordered stage traces with source-event id and max input close time.

Assert equality (or an explicit deterministic tolerance for floating point) for: watcher admission; Engine output; Fusion inputs and outputs; aggregator ranking; manager evaluations and selected strategy; `ExecutionIntent` side, confidence, SL/TP and relevant metadata; risk decision/reason and final pre-broker order. Assert one intent yields at most one pre-broker order/guard decision. Only the data-source transport, broker fill/latency/fee model and downstream reconciliation may differ. Compare configuration/timeframe binding for all instantiated adapters, not just the selected one. Normalize nondeterministic IDs and wall-clock logging, never decision timestamps. If source event kinds differ, do not force a misleading equality claim.

**Prefix invariance:** process prefix through T, then the same prefix plus future T+N; hash normalized features, interpreted/fused signals, selected strategy, intent and risk decision at every timestamp `<=T`. Any change fails causal integrity. Include rolling warmup, NaN/gap, same-bar high/low, UTC boundary, MTF close alignment and reconnect cases. Add a direct test proving a later first-valid SMA/ATR cannot populate an earlier warmup row. Verify historical data/simulation adapters have no authenticated broker call path. No profitability assertion follows automatically from passing parity.

Minimum expected existing-file touch set: `application/use_cases/run_backtest.py` (delegate canonical replay and remove unsafe fill from that route); `infrastructure/backtest/strategy_provider.py` (retire mock-fused adapter path from canonical use, retaining legacy only if needed); `infrastructure/backtest/realistic_backtester.py` (separate downstream fill/metrics from upstream strategy decision); `infrastructure/orchestrators/architecture_orchestrator.py` and/or `infrastructure/messaging/event_system.py` (inject event-time source and simulated execution port without strategy/domain mode branches); `infrastructure/aggregators/signal_aggregator.py` (deterministic replay/flush seam if needed). Exact edit count is not knowable until the offline trace resolves the route; avoid touching adapters/strategies/settings/risk rules. First implementation unit should be route-trace tests only, then separately reviewed minimal code edits.

## H. RISKS / REGRESSION SURFACE

Highest risks: double execution from two live intent subscribers; wall-clock/threads changing event order; accidental broker calls from simulated routing; strategy state/cooldowns and outcome feedback differing under replay; historical OHLCV as an insufficient proxy for live watcher inputs; open versus closed candle semantics; backtester-specific leverage/short, fee and fill behavior; losing comparability with old research outputs. Pin source timestamp/provenance and keep old results explicitly noncanonical. Test both long/short and no-trade. Deployment remains NO_TRADE_DEFAULT until separately reviewed; this design makes no assertion of edge or profitability.
